# 真实底片采集与标注作业指导书

> 制定日期：2026-10-11
> 前置事实：**公开数据榨不出真实域覆盖**（见 `runs/eval-cross/CROSS_DOMAIN_REPORT.md` §4.8）。
> 现状：全项目真实底片**只剩 1 张唯一内容**（解密出的 2 个文件 md5 相同），且无标注。

---

## 1. 为什么这批数据是当前唯一的 P0

三组实测把话说死了：

| 观测 | 数值 | 含义 |
|---|---|---|
| 公开数据训练 → 产品真实输入域 | mAP50 0.9705 | 同来源图像的域变换，能救 |
| 公开数据模型 → **真实现场底片** | 与产品模型检出**零重合**（12 个组合 agree=0.000） | 跨来源，救不了 |
| 公开训练集里的 **未焊透 / 内凹** | **0 实例** | 模型结构上不可能输出这两类 |
| 产品模型在真实底片的检出里 **未焊透占** | **76%**（44/58） | 而它恰是公开集没有的那类 |

**结论**：训推一致化 + 翻拍增强解决的是"分布变换错配"（+11～26 pt，已确认有效）；
它解决不了"数据源不同"。**真实域覆盖只能靠真实底片。**

另外，项目原 Golden Set（136 图 / 719 框）已遗失，导致现在**无法回答"模型有没有变好"**。
这批真实底片的评估子集就是**新的 Golden Set**。

## 2. 采多少

### 2.1 统计力下限（95% 置信区间 ±10 pt 所需）

| 某类真实占比 | 需命中次数 | 累计底片数（估） |
|---|---|---|
| 50% | ~97 | ~200 |
| 20% | ~62 | ~310 |
| 10% | ~35 | ~350 |
| 5% | ~19 | ~380 |

> 注：这是"要能报出精度"的要求。**当前阶段不需要这么多** —— 见下。

### 2.2 分阶段目标（务实）

| 批次 | 张数 | 用途 | 目的 |
|---|---|---|---|
| **第 1 批** | **20–30 张** | **评估（冻结）** | 拿到第一个"真实域分数"，取代丢失的 Golden Set |
| 第 2 批 | 50–100 张 | 训练 | 真正把真实域补进训练集 |
| 持续 | 累计 ≥300 张 | 评估+训练 | 才谈得上"能报精度" |

**第 1 批的最低要求（缺一不可）**：

- [ ] **覆盖全部 7 类**，尤其是 **未焊透** 与 **内凹**（这两类现在一个实例都没有）；
- [ ] 每类 ≥ **5 个实例**（不是 5 张图 —— 一张图上同一类算 1 个实例）；
- [ ] 包含**无缺陷**的正常片若干（否则测不出误检率）；
- [ ] 包含**有印字/铅字**的片子（这是首要误检源，必须有样本能量化）；
- [ ] 记录每张的**焊接方式**（单面焊/双面焊）—— 直接影响 `std501807.py` 的重点类判定。

**不要挑片子。** 只挑"有典型缺陷的漂亮片子"，会得到一个严重高估的分数。
随机抽产线上的片子，哪怕一半是没缺陷的。

## 3. 怎么采（现场）

### 3.1 优先要"原始件"，不要截图

| 优先级 | 形式 | 说明 |
|---|---|---|
| ★★★ | 数字成像原始文件（DICONDE / TIFF 16bit） | 信息无损，可复现产品链路 |
| ★★ | 胶片**扫描**件（≤ 50 µm 扫描） | 保持灰度线性，注意扫描仪本身的一致性 |
| ★ | 翻拍照片（手机/相机拍灯箱上的胶片） | 可用，但**必须记录翻拍条件**（灯箱亮度、相机、是否贴平） |

**最忌讳**：微信传输后被压缩的图、截图后二次压缩的图。这类图会永久污染数据集。

### 3.2 若必须翻拍，按此规范

1. **贴平**：胶片与灯箱之间不留缝隙，避免反光斑；
2. **曝光**：不要把焊缝拍成纯黑或过曝，直方图两端各留 5% 余量；
3. **不裁切**：保留整张胶片（含边框和印字）—— 产品推理链路会自己做 `film_region` 检测与印字区过滤，裁了反而偏离真实输入；
4. **不要后期处理**：不加滤镜、不调对比度、不美颜、不锐化；
5. **同批同条件**：同一批片子用同一套灯箱/相机/距离，避免引入批次差异。

### 3.3 命名与元数据

文件名随意（入库脚本按**像素内容**去重，不怕重名），但请在采集目录放一个
`meta.csv`（可后补）：

```csv
文件名,焊接方式,板厚mm,材质,透照方式,是否含缺陷,备注
IMG_0231.jpg,单面焊,8,Q345B,双壁单影,是,根部未焊透
```

`焊接方式` 和 `板厚` 是后续做分层评估的必要字段。

## 4. 采回来怎么做（三步）

```bash
# ① 入库：解密（若为 SDC2 密文）→ 按像素去重 → 归档 → 缩略图 → 台账 → 待标注清单
python scripts/ingest_real_films.py --src D:/新采底片 --key-file data/.crypto_key

# ② 按 data/real/WORKLIST_<日期>.md 逐张标注（产物写到 data/real/labels/<chash>.txt）
#    标注工具：项目自带 backend/annotator/server.py

# ③ 校验：越界/类别/空标/极小框/重复框/图失配 —— 有 ERROR 就禁止进训练
python scripts/validate_labels.py --labels data/real/labels --images data/real/images

# ④ 刷新台账与清单（标注完成后）
python scripts/ingest_real_films.py --src data/real/raw --refresh-only
```

入库后目录结构：

```
data/real/
  raw/<chash>.png      原始文件留档
  images/<chash>.png   灰度底片
  thumbs/<chash>.jpg   标注用缩略图
  labels/<chash>.txt   7 类 YOLO 标注
  INDEX.csv            台账（Excel 可开）
  registry.json        机读台账
  WORKLIST_<日期>.md   待标注清单
```

## 5. 标注规范

### 5.1 格式与口径

YOLO 格式，每行 `类别id 中心x 中心y 宽 高`，坐标归一化到 0–1。

**类别口径唯一权威**：`backend/domain/dto.py` 的 `DefectClass`

| id | 类别 | 影像特征（标注依据） |
|---|---|---|
| 0 | 气孔 | 黑色圆形/椭圆形，中心黑度高、边缘低 |
| 1 | 夹渣 | 黑点/黑条/黑块，形状不规则、轮廓不圆滑、黑度变化无规律 |
| 2 | **未焊透** | **细直黑线**，两侧轮廓整齐（钝边加工痕迹），位于**焊缝根部投影**（常在焊缝中部），可断续可连续，有时贯穿整张底片 |
| 3 | 未熔合 | 黑色长条状，位置偏焊缝边缘或层间，一侧轮廓齐一侧不规则 |
| 4 | 裂纹 | 黑色细线条，中间略宽两端尖细，轮廓分明 |
| 5 | 咬边 | 沿焊缝边缘的暗黑色**波浪状**线条 |
| 6 | **内凹** | 焊缝根部不规则、**边缘模糊**的黑影，**中部黑度较大、向边缘渐淡** |

> ⚠️ 常见误解：**内凹不是亮带**。内凹与未焊透在底片上**都是暗影**（黑度增加）。

### 5.2 两条铁律

1. **只标看得准的框。** 拿不准的不标。行业里"标错"比"少标"危害小得多 ——
   错标会让模型学到错误的形状判据。
2. **漏标 = 负向污染。** 图上明明有缺陷却不标，等于给模型灌"这里没东西"的标签。
   宁可这张图不标（但要在 `meta.csv` 里注明），也不要漏标。

### 5.3 必须做的一致性检查

多人标注时，先各自标 **5 张**，比对框的差异（IoU < 0.5 的地方要讨论统一口径），
再开始批量标。这一步省不得 —— 口径不统一会让评估数字失去意义。

## 7. 采集之后会发生什么（预期收益）

1. **先得到"真实域分数"** —— 这是目前完全空白的一格，也是判断"模型能不能用"的唯一依据；
2. 用真实域分数**验证翻拍增强策略是否真的有效**（当前只有合成代理域的间接证据）；
3. 若第 2 批入训练集，可将 **未焊透/内凹** 从"结构上不可能输出"变为"可输出"；
4. 恢复 Golden Set 功能 → 后续任何改动都能回答"变好了还是变差了"。
